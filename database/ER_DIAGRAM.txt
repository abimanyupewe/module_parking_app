2. TABEL DAN RELATIONSHIP SUMMARY
═════════════════════════════════════════════════════════════════════════════════

TABEL 1: TB_JENIS_KENDARAAN (MASTER - Root of hierarchy)
─────────────────────────────────────────────────────────
Hubungan Output:
  • 1:Many → TB_AREA_PARKIR (area hanya untuk satu tipe kendaraan)
  • 1:Many → TB_KENDARAAN (kendaraan memiliki tipe tertentu)

Contoh: jenis_id = 1 (Motor) → bisa ada 100+ Motor berbeda di TB_KENDARAAN
        jenis_id = 1 (Motor) → bisa ada area khusus di TB_AREA_PARKIR


TABEL 2: TB_AREA_PARKIR (MASTER - Area management)
──────────────────────────────────────────────────
Hubungan:
  • Foreign Key: jenis_id → TB_JENIS_KENDARAAN
  • 1:Many: → TB_TRANSAKSI (banyak transaksi bisa di area yang sama)

Contoh: area_id = 2 (Lantai 2 Mobil) hanya untuk jenis_id = 2
        Bisa ada 50+ transaksi di area_id = 2


TABEL 3: TB_KENDARAAN (MASTER - Vehicle registry)
──────────────────────────────────────────────────
Hubungan:
  • Foreign Key: jenis_id → TB_JENIS_KENDARAAN
  • 1:Many: → TB_TRANSAKSI (satu kendaraan bisa parkir berkali-kali)

Contoh: kendaraan_id = 5 (Plat H 1234 ABC - Motor Honda Merah)
        Bisa punya 10+ transaksi (parkir 10 kali di waktu berbeda)


TABEL 4: TB_USER (MASTER - Users)
──────────────────────────────────
Hubungan Output:
  • 1:Many → TB_TRANSAKSI (user/petugas mencatat banyak transaksi)
  • 1:Many → TB_LOG_AKTIVITAS (setiap user punya banyak log aktivitas)

Contoh: user_id = 3 (Petugas Andi) mencatat 100+ transaksi


TABEL 5: TB_TRANSAKSI (TRANSACTION - Core business logic)
──────────────────────────────────────────────────────────
Hubungan Input (Foreign Keys):
  • kendaraan_id → TB_KENDARAAN (mobil apa)
  • area_id → TB_AREA_PARKIR (di mana)
  • user_id → TB_USER (siapa yang catat)

Terdiri dari: Catatan SETIAP parkir (masuk-keluar)


TABEL 6: TB_LOG_AKTIVITAS (LOG - Audit trail)
──────────────────────────────────────────────
Hubungan Input:
  • user_id → TB_USER (user mana yang action)

Terdiri dari: Catatan semua aktivitas untuk keamanan & monitoring


3. RELASI DETAIL DENGAN CARDINALITY
═════════════════════════════════════════════════════════════════════════════════

Relasi 1: TB_JENIS_KENDARAAN ─[1:Many]─→ TB_AREA_PARKIR
├─ 1 Jenis Kendaraan → Banyak Area
├─ Contoh: 1 "Motor" → Lantai 1 Motor, Lantai 2 Motor, Basement Motor (3 areas)
└─ Foreign Key: TB_AREA_PARKIR.jenis_id

Relasi 2: TB_JENIS_KENDARAAN ─[1:Many]─→ TB_KENDARAAN
├─ 1 Jenis Kendaraan → Banyak Kendaraan
├─ Contoh: 1 "Motor" → H 1234 ABC, H 2020 XYZ, H 3333 PQR (3 vehicles)
└─ Foreign Key: TB_KENDARAAN.jenis_id

Relasi 3: TB_KENDARAAN ─[1:Many]─→ TB_TRANSAKSI
├─ 1 Kendaraan → Banyak Transaksi (bisa parkir berkali-kali)
├─ Contoh: Plat H 1234 ABC parkir 5 kali (5 transaksi)
└─ Foreign Key: TB_TRANSAKSI.kendaraan_id

Relasi 4: TB_AREA_PARKIR ─[1:Many]─→ TB_TRANSAKSI
├─ 1 Area → Banyak Transaksi (banyak mobil parkir di area)
├─ Contoh: Lantai 2 Mobil punya 50 transaksi aktif
└─ Foreign Key: TB_TRANSAKSI.area_id

Relasi 5: TB_USER ─[1:Many]─→ TB_TRANSAKSI
├─ 1 User/Petugas → Banyak Transaksi (catat transaksi berkali-kali)
├─ Contoh: Petugas Andi mencatat 100+ transaksi
└─ Foreign Key: TB_TRANSAKSI.user_id

Relasi 6: TB_USER ─[1:Many]─→ TB_LOG_AKTIVITAS
├─ 1 User → Banyak Log (aktivitas demi aktivitas)
├─ Contoh: Owner login 50+ kali (50 log)
└─ Foreign Key: TB_LOG_AKTIVITAS.user_id


4. NORMALISASI DATABASE
═════════════════════════════════════════════════════════════════════════════════

✓ SUDAH MEMENUHI 3NF (Third Normal Form)

1NF (First Normal Form):
✓ Setiap kolom berisi atomic value (tidak ada repeating groups)
✓ Contoh: role adalah TEXT tunggal, bukan array
✓ Setiap tabel punya Primary Key

2NF (Second Normal Form):
✓ Semua non-key attributes depend pada PRIMARY KEY penuh
✓ Tidak ada partial dependencies
✓ Contoh: nama_area di TB_AREA_PARKIR bergantung pada area_id (bukan jenis_id)

3NF (Third Normal Form):
✓ Tidak ada transitive dependencies
✓ Setiap non-key attribute independent dari attribute lain
✓ Contoh: tarif_per_jam disimpan di TB_JENIS_KENDARAAN, bukan di TB_AREA_PARKIR

7. QUERY UNTUK BERBAGAI USE CASE
═════════════════════════════════════════════════════════════════════════════════

USE CASE 1: DASHBOARD OWNER - Total Pendapatan Harian
───────────────────────────────────────────────────────
SELECT 
  DATE(waktu_masuk) as tanggal,
  COUNT(*) as jumlah_transaksi,
  SUM(total_biaya) as total_pendapatan
FROM tb_transaksi
WHERE status = 'keluar'
  AND DATE(waktu_masuk) = '2024-01-15'
GROUP BY DATE(waktu_masuk);

Hasil:
  tanggal: 2024-01-15
  jumlah_transaksi: 150
  total_pendapatan: Rp750000


USE CASE 2: DASHBOARD ADMIN - Status Area Parkir Sekarang
──────────────────────────────────────────────────────────
SELECT 
  ap.nama_area,
  jk.nama_jenis,
  ap.kapasitas,
  ap.terisi,
  (ap.kapasitas - ap.terisi) as kosong,
  ROUND(CAST(ap.terisi AS FLOAT) / ap.kapasitas * 100, 1) as persen_penuh
FROM tb_area_parkir ap
JOIN tb_jenis_kendaraan jk ON ap.jenis_id = jk.jenis_id
ORDER BY persen_penuh DESC;

Hasil:
  Lantai 2 Mobil    | Mobil  | 50 | 48 | 2  | 96.0%
  Lantai 1 Motor    | Motor  | 100| 87 | 13 | 87.0%
  Basement Motor    | Motor  | 80 | 45 | 35 | 56.3%


USE CASE 3: PETUGAS - Lihat Kendaraan yang Masih Parkir
────────────────────────────────────────────────────────
SELECT 
  t.transaksi_id,
  k.plat_nomor,
  jk.nama_jenis,
  ap.nama_area,
  t.waktu_masuk,
  CAST((julianday('now') - julianday(t.waktu_masuk)) * 24 AS INTEGER) as lama_jam
FROM tb_transaksi t
JOIN tb_kendaraan k ON t.kendaraan_id = k.kendaraan_id
JOIN tb_jenis_kendaraan jk ON k.jenis_id = jk.jenis_id
JOIN tb_area_parkir ap ON t.area_id = ap.area_id
WHERE t.status = 'parkir'
ORDER BY t.waktu_masuk;

Hasil:
  transaksi_id=45, plat='H 1234 ABC', jenis='Motor', area='Lantai 1', lama_jam=2
  transaksi_id=46, plat='B 5678 CDE', jenis='Mobil', area='Lantai 2', lama_jam=1


USE CASE 4: AUDIT - Aktivitas User
───────────────────────────────────
SELECT 
  u.nama_lengkap,
  l.kategori_log,
  l.aktivitas,
  l.waktu
FROM tb_log_aktivitas l
JOIN tb_user u ON l.user_id = u.id_user
WHERE DATE(l.waktu) = '2024-01-15'
ORDER BY l.waktu DESC;

Hasil:
  Owner        | Laporan | Cetak laporan harian      | 17:00:00
  Andi Petugas | Input   | Kendaraan keluar H 1234   | 10:30:00
  Andi Petugas | Input   | Kendaraan masuk H 1234    | 08:00:00
  Owner        | Otorisasi| Login ke sistem           | 08:00:00
